## Per-item loop

1. Compose — leitmotifs → `compositions/leitmotifs/`, loops → `plans/` +
   `npm run song:build`, scene/battle cues → `compositions/segments|loops/`.
2. `npm run composition:validate -- --file <path>`
3. `npm run render -- --file <path>` (re-render with `--force` after any edit).
4. User auditions at `npm run app` → one adjustment.
5. On approval: copy the piece + its MP3 into `tasks/redwater/<category>/` and
   mark `done` here.

Naming: `redwater-<slug>` everywhere so products trace back to this work order.

## Quoting The Unhoming

Settled, so eleven cues don't each re-decide it. **The theme is
`redwater-unhoming`** — four bars, two voices, nothing else. The 22-bar
arrangement is `redwater-unhoming-title` and is *never* what gets quoted: a
quote is a phrase recognised over whatever is already playing, and dropping a
main title into a battle loop is copying the piece instead.

```bash
npm run motif:quote -- --into compositions/loops/<piece>.json \
    --motif redwater-unhoming --at-bar <n> --octave -1 --intensity 0.7
```

- `--octave -1` by default. The cell sits at G3–F4; under a cue with its own top
  line it wants to be below that line, not next to it.
- `--intensity 0.6–0.7` for battle and scene loops (it is a reference, not the
  tune), `0.85` for the moments where the party *is* the subject.
- Quote the whole four bars, or the first two — the rising fifth is the
  recognisable half, and the walk down is the part you can cut for room.
- Re-render the host afterwards with `--force`; the audio has no idea the notes
  moved.

**Careful:** `motif:quote` takes whole tracks and has no bar range, and its
"carries the tune" filter excludes `drums`/`bass`/`pad` but *not* `pluck`. So a
motif with a rhythm-guitar part would have that quoted as if it were the theme.
The cell has no `pluck` track, which is why it is a separate file.
